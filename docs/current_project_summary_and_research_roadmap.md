# 设施大棚根区水分MPC项目总结与后续研究思路

更新日期：2026-09-20

证据基线：截至T059的冻结实验、软件在环结果和任务台账

## 一、当前判断

本项目可以支撑研究生毕业设计，但研究命题必须保持为“智慧管控平台主体＋根区水分MPC适用性与失效边界”。当前最可靠的贡献不是证明MPC全面优于规则控制，而是建立一条可追溯的研究链：数据质量检查、辨识信息准入、双层根区模型、规则与MPC冻结对照、异常条件下的失败边界，以及任务—命令—反馈的软件审计。

项目已经完成59项登记任务，99项测试全部通过。纯Python已覆盖模型、控制、统计评价、数据质量、标定质量、动态误差分解、MQTT和软件在环，MATLAB只需在导师要求Simulink展示或独立数值复核时使用。

当前证据全部来自仿真、合成数据或本机软件在环。项目尚未取得红壤实测参数、真实传感器回放和实体控制对照，因此不能声称红壤现场有效、真实节水、增产或提高肥料利用率。

当前阶段已经从“直接起草毕业论文”纠正为“先在学校定版底稿上完成开题报告修订”。第2—8章草稿只作为研究结构和证据储备，不作为当前交付物。开题报告修订稿保留智慧管控平台主体，把算法研究收束为有限数据准入、双层根区灰箱模型、强规则与MPC冻结评价、可信监督失效边界和平台审计，并明确只有仿真与软件在环条件。

最终题名确定为“基于物联网与协同控制的智能水肥一体化管控系统设计与实现——以红壤丘陵区为例”。题名以物联网管控系统为总体对象，将红壤丘陵区作为应用场景，用于提出地形起伏、生产单元分散、通信波动和设备状态差异条件下的系统需求；算法主线仍是混肥EC闭环中的云边协同控制：云端执行时间戳预测控制，边缘端提供本地PI接管，观测进一步失效时进入模型锚定降级，监督器综合通信风险与观测风险，在M0、M1、M2之间进行带滞回和恢复确认的切换。该场景限定不构成红壤区域节水、增产或肥效结论。根区水分MPC路线作为仓库既有研究储备保留，不再承担本版开题报告的核心叙事。

T036曾确认第3章的15 min双层灰箱辨识链与T010的1 h单层MPC评价链不兼容。T037至T041没有改写旧实验，而是新建一条接口统一的双层端到端链路：独立对象生成数据，数据通过信息准入，模型在独立循环验证后进入MPC，控制器经开发集冻结，再在90个锁定场景确认。R027现已完成。

T037现已冻结双层端到端补建协议，规定独立非线性对象、6＋3个开发循环、先信息准入后模型拟合、命令—实际灌水映射、双层控制代价、36个开发场景和90个锁定场景。后续实现必须按该协议推进，锁定结果不得用于追溯调参。

T038完成独立双层对象和辨识数据入口。873行、6＋3个循环的数据通过全部质量检查和信息准入，最弱信息量为133.715，预测归一化标准误为0.004745。

T039使用6个辨识循环拟合双层灰箱模型，并在3个预留循环的288个转移上完成冻结验证。浅、深层单步技能为0.672和0.275，整循环技能为0.960和0.936，8项判据全部通过。T040在36个开发场景中冻结`TLR001`和`TLM004`，未访问90个锁定场景。

T041在90个锁定场景中得到`JOINT_VALUE_SUPPORTED`：MPC命令灌水配对中位差为−6.5 mm，加权亏缺配对中位差为−0.000314，两者95% bootstrap区间上界均小于0；联合不劣比例75.56%，任一主要终点恶化比例24.44%，安全违反场景均为0。结果通过预设门，但任一终点恶化比例距离25%上限很近，且MPC动作变化中位增加130次。论文应把“合成对象上的联合价值支持”和“动作频繁、现场未验证”同时陈述。

## 二、已经形成的完整技术链

```text
现场/合成观测
  → 结构与水量账质量闸门（T023）
  → 激励信息与模型准入闸门（T026–T027）
  → 双层根区灰箱模型辨识与独立循环验证（T024）
  → 强规则基线与区间MPC冻结对照（T008–T010）
  → 异常注入、可信回退与停止规则（T011、T013–T018）
  → 任务、版本、命令、联锁、反馈和MQTT审计（T012、T021–T022）
  → 真实数据回放或低风险实体验证（当前缺失）
```

### 1. 数据与模型层

现场模板已固定双深度水分、实际灌水、流量、累计水量、棚内温湿度、太阳辐射、人工参考水分、根深和生育阶段。T023设置20项基础质量检查，并强制3个辨识循环与2个验证循环用途隔离。

T024建立双层灰箱模型辨识入口。合成样例的一步预测技能值为0.911和0.872，整循环技能值为0.809和0.591；但深层交换系数命中下界0，说明预测精度不能替代参数可辨识性判断。

T025进一步证明多样化激励可使参数RMSE降至弱激励的0.251、共同探针RMSE降至0.558，但原冻结的标准化条件数判据失败。T026改用保留幅值、按参数范围和噪声缩放的信息量：强/弱信息量比为2.153，预测不确定性比为0.515，实际参数误差比为0.252。该指标可以区分采样设计等级，但组内相关较弱，不能预测某一次拟合的具体误差。

T027把信息量接入模型准入。240行合成样例虽然通过基础质量，仍因三个辨识循环激励重复而被判定为`collect_more_excitation`。这使平台能够区分“数据文件合格”和“数据足以支持当前模型”。

T030至T032补齐了水分传感器与流量计标定入口、区间输入时间对齐和动态误差分解。当前合成标定噪声传播后，浅层和深层已知误差方差分别为验证残差方差的96.25倍和360.53倍，流程因此拒绝生成过程噪声候选。该拒绝揭示两组合成样例尺度不相容，也防止用负剩余方差制造“零过程噪声”。

### 2. 控制算法层

早期单层MPC与强规则在120个独立锁定场景中形成“少灌水伴轻微亏缺增加”的权衡：命令灌水中位数减少6 mm，亏缺积分中位数增加0.000680，联合不劣比例40.83%。该结果保留为算法演进和评价方法证据。

新的双层集成链以通过准入的灰箱模型直接驱动MPC。在90个独立锁定场景中，命令灌水中位差为−6.5 mm，加权亏缺中位差为−0.000314，联合不劣比例75.56%，得到有限合成边界内的联合价值支持。浅层亏缺大多等价，主要改善来自深层亏缺；MPC在全部场景增加动作变化，配对中位增加130次。

这一结果仍有研究价值。它给出了MPC相对规则控制的适用条件、代价函数敏感性和动作频繁问题，并说明评价必须同时报告灌水投入、亏缺、过湿、安全和动作次数，不能用单一综合分数掩盖权衡。

### 3. 可信监督层

V1风险监督能够发现异常，但只在1类异常上改善、在6类异常上恶化。V2使用估计状态驱动回退后改善其中5类，却在反馈冲突后出现3个过湿安全失败；原因是高风险同时触发回退和禁止观测校正，异常结束后形成恢复死锁。V3增加恢复探测、硬过湿保护和滚动灌水预算后消除了开发集安全失败，但没有候选在机制价值上超过V2，因此按预设停止规则终止，没有使用锁定集。

这些失败结果应作为论文的失效机理证据。它们支持“异常检测不等于有效回退”“状态隔离需要独立恢复通道”“统一灌水预算对传感异常和执行故障可能产生相反影响”。在没有新观测通道或现场残差数据前，继续开发V4只会扩大调参空间，不应作为当前优先工作。

### 4. 智慧管控平台层

平台已实现任务、算法版本、命令、反馈、联锁和模式切换的追溯。基础软件在环完成1008个控制步、命令和反馈的一一关联。可靠消息试验覆盖重复、乱序、超时和进程异常退出恢复。本地MQTT 3.1.1与QoS 1试验完成持久会话、离线消息补发、代理重启重连、应用层幂等和异常时间戳拒绝。

平台证据目前支持本机确定性软件语义，尚不支持真实网络拥塞、PLC、断电或泵阀实时可靠性。毕业设计的平台贡献可以成立，但表述应为“软件在环验证的智能管控平台原型”。

## 三、毕业设计应回答的三个核心问题

### 问题1：有限数据何时足以进入根区模型辨识？

采用“结构质量＋激励信息”两级准入。循环数量只作为最低入口，真正停止补采的依据是信息量、预测不确定性、参数稳定性和独立循环验证共同通过。该问题对应当前最明确的算法创新点，也直接回应水肥一体化MPC数据不足的问题。

### 问题2：根区MPC在哪些条件下值得替代强规则？

以强规则为必要基线，在冻结场景中同时比较水分亏缺、过湿、灌水量和动作代价。目标不是寻找所有指标上的单一赢家，而是识别MPC能够形成可接受权衡的参数区间，以及蒸散预测误差、根深变化和执行能力下降时的失效边界。

### 问题3：算法怎样以可审计方式进入智慧管控平台？

每次控制必须绑定模型和控制器版本，并记录观测、风险状态、决策模式、命令、联锁及反馈。数据未通过准入时不得冻结模型；控制器不可用或观测异常时必须产生可解释的模式状态。该问题把算法研究与开题报告的平台主体连接起来。

## 四、建议凝练的创新点

可以稳定写入毕业论文的创新点：

1. 面向根区MPC有限数据问题，提出结构质量与幅值敏感信息量结合的两级模型准入流程；
2. 建立强规则基线下的冻结配对评价方法，给出根区MPC节水—亏缺权衡及适用边界；
3. 将模型版本、控制模式、联锁、命令与反馈统一纳入可追溯平台，并通过异常消息软件在环验证关键语义；
4. 通过V1—V3受控迭代揭示可信回退的恢复死锁与安全预算冲突，形成可复核的否定性机制证据。

只有取得真实数据后才能增加的创新点：红壤参数辨识、真实数据回放性能、现场噪声下的信息准入阈值和低风险实体控制效果。

不应使用的主张包括“实现精准水肥最优控制”“MPC显著优于传统方法”“验证红壤节水增产效果”和“可信监督保证系统安全”。当前证据不支持这些表述。

## 五、从现在到毕业论文的执行路线

### 阶段A：无现场数据时立即完成

1. 冻结当前算法范围，不继续无边界开发V4；
2. 建立传感器重复标定、流量标定和人工含水率参考记录模板；
3. 建立一键证据审计，自动检查任务状态、配置哈希、结果文件、数据角色隔离和论文数字来源；
4. 按“平台—数据准入—模型—MPC对照—失败边界”重构毕业论文目录和章节证据表；
5. 若导师需要演示，再开发最小工作台界面；界面只展示任务、数据准入、模型版本、控制模式、命令反馈和风险状态。

### 阶段B：取得最低现场数据后

1. 先完成水分传感器与流量计标定，估计现场测量噪声；
2. 导入至少3个辨识循环和2个冻结验证循环，运行T023与T027；
3. 信息不足时逐循环补采，优先改变安全范围内的初始浅深水分梯度、实际灌水量/时刻和天气覆盖；
4. 准入后拟合双层灰箱模型，在两个独立循环上检查一步预测、整循环预测、方向偏差、物理边界和参数稳定性；
5. 模型未通过时先缩减结构或固定弱可辨识参数，不允许读取验证集反复调结构。

### 阶段C：模型通过后

1. 用实测天气与执行反馈进行规则和MPC离线回放；
2. 冻结代价函数与安全约束，再使用独立时段评价；
3. 有实体条件时先做影子控制或低风险分区试验，MPC只给建议、不直接驱动泵阀；
4. 只有在联锁、人工接管和流量反馈可靠后，才进入短周期闭环对照。

## 六、成功与停止条件

仓库既有根区MPC路线已经形成可运行、可追溯的仿真版本：数据准入与辨识流程可执行，通过准入的双层模型已经驱动MPC并完成冻结评价，监督失效边界得到记录。T053采用另一条更贴合小论文的毕业设计主线，最低成功条件为：复现RA-ECSC三模式监督，完成代表性网络与传感异常下的冻结配对仿真，实现MQTT边云消息链和状态同步，并用超差时间、跟踪误差、执行器总变差、切换次数与安全约束共同验证。两条路线共享平台与验证方法，但正文不得把根区MPC结果当作EC闭环结果。

更强版本需要真实传感校准、至少3＋2个信息充分的湿干循环、独立模型验证和真实数据回放。实体控制、真实节水率与作物效果属于附加层，不应设为在当前资源条件下毕业成立的唯一前提。

出现以下情况时应停止对应路线：安全约束下无法获得足够激励时缩减模型；独立验证失败时不进入MPC现场比较；监督算法增加安全违反时停止晋级；没有独立流量和储水核算时不报告节水率；没有生物学重复和完整生育期时不报告产量或品质效果。
