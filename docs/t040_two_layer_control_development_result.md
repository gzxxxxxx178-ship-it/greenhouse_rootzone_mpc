# T040 双层规则与MPC开发选择结果

## 目的与证据边界

本任务使用通过T039独立验证的双层灰箱模型，在独立双层非线性对象上完成规则控制器和MPC控制器的有限候选选择。结果只属于合成对象上的开发集选择，不能作为红壤现场有效性或MPC优越性结论。

候选、可行性门和排序规则在首次开发运行前冻结于`configs/two_layer_control_development_v1.yaml`。开发选择只运行36个开发场景；同一清单内的90个锁定评价场景没有进入控制仿真或参数选择。

## 冻结设计

- 规则候选8组，MPC候选8组；两类候选均未超过协议上限。
- 可行性要求为安全违反场景数等于0、加权亏缺积分中位数不高于0.01、P90不高于0.05。
- 可行候选依次按命令灌水中位数、加权亏缺中位数、动作变化中位数和候选编号升序选择。
- 两类控制器在同一场景内共享天气、对象参数、初始状态和随机种子，并分别记录命令灌水与实际到达灌水。

## 结果

16组候选全部通过可行性门。冻结规则控制器为`TLR001`：浅层/深层启动阈值0.200/0.210 m³/m³，停止阈值0.225/0.235 m³/m³，单步命令0.5 mm，最小启停保持均为2步。其36场景命令灌水中位数为47.0 mm，加权亏缺积分中位数为0.0004869，P90为0.0075425，动作变化中位数为6次，安全违反场景数为0。

冻结MPC控制器为`TLM004`：干旱、过湿、水量、动作变化和终端权重分别为20000、4000、0.05、0.05和2.0。其命令灌水中位数为38.25 mm，加权亏缺积分中位数为0.0001748，P90为0.0055902，动作变化中位数为134.5次，安全违反场景数为0。

开发集上MPC比规则少8.75 mm命令灌水且亏缺中位数更低，但动作切换明显增加。该现象只能作为T041锁定评价的待验证方向，不能提前分类为控制价值成立。对象最大绝对水量平衡残差为3.31×10⁻¹⁴ mm。

## 可重复性与交接

拆分配置前的两次完整复算中，场景清单、576行开发运行表和16行候选汇总表的SHA-256均一致。配置拆分修复后再次运行，三项科学数据哈希保持不变；正式结果绑定代码提交`91f0ca7`、控制开发配置、T039模型结果和126场景清单哈希。

冻结控制器写入`configs/two_layer_frozen_controller_v1.yaml`。下一阶段只能在90个锁定场景上比较`TLR001`和`TLM004`，不得依据锁定结果修改本配置、候选选择或评价门槛。本任务未生成结果图。
