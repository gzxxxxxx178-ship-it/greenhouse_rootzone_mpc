# 根区MPC可信回退与恢复设计

## 设计目标

T010表明基础MPC能稳定减少仿真灌水命令量，但多数场景存在轻微亏缺增加，蒸散低估和浅根区条件更不利。监督器的目标是识别MPC当前是否适合继续参与控制，减少异常造成的亏缺和执行失败，同时保留可解释的灌水投入权衡。

## 模式

| 模式 | 用途 | 允许动作 |
|---|---|---|
| `mpc` | 观测、模型、求解和执行状态满足条件 | 执行MPC候选灌水量 |
| `rule_fallback` | MPC不可用或风险较高，但基本观测和执行链仍有效 | 执行经冻结的规则控制 |
| `safe_pause` | 关键观测失效或执行链不可信 | 暂停自动灌溉并请求人工处理 |

`safe_pause`是软件状态，不证明作物安全。长期暂停可能造成水分亏缺，平台必须记录告警、持续时间和人工处置。

## 风险输入

- 观测风险：数据时效、量程、变化速率，以及存在冗余传感器时的一致性。
- 模型风险：一步预测残差的平滑量及预测区间越界情况。
- 执行风险：命令后流量不足、阀门反馈冲突和陈旧回执。
- 离散状态：观测是否有效、求解是否成功、执行器是否可用、反馈是否一致。

未来蒸散真实误差在控制时刻不可直接获得，因此不能把“真实预测偏差”作为在线风险输入。监督器只能使用到当前时刻已经获得的预测残差和观测信息。

## 转移优先级

1. 关键观测无效、执行器不可用或反馈冲突时，优先进入`safe_pause`。
2. 求解失败，或观测、模型风险达到高阈值时，从`mpc`转入`rule_fallback`。
3. 从`safe_pause`恢复时先进入`rule_fallback`，不得直接返回`mpc`。
4. 仅当各风险连续满足恢复阈值、求解成功且达到最小驻留时间后，才从`rule_fallback`返回`mpc`。
5. 高风险阈值与恢复阈值分离，形成滞回。

## 后续验证要求

- 在开发场景中校准风险归一化尺度和阈值，锁定评价集不参与选择。
- 正常工况必须报告监督机制的误回退率和额外动作代价。
- 异常工况至少覆盖蒸散持续低估、模型参数突变、观测偏置／漂移／缺测、求解失败、流量衰减及反馈冲突。
- 比较基础MPC、固定判据回退和完整可信监督，不允许只与无保护方法比较。
- 主要结果联合报告亏缺积分、灌水命令量、动作次数、安全违反、暂停持续时间和恢复时间。

## 已知边界

- 单一土壤水分传感器的缓慢漂移可能与真实土壤变化混淆。
- 模型残差同时受到模型失配、蒸散误差和传感异常影响，不能直接解释为特定故障诊断。
- 没有实体泵阀和传感器时，执行风险只能通过软件故障注入评价。
