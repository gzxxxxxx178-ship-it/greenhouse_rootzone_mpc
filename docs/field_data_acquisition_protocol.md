# 根区MPC最低现场数据采集与质量闸门

## 目标与适用范围

本协议用于把后续红壤土柱、盆栽或单个棚内低风险分区的数据接入根区模型辨识与独立验证。当前规定的是“可以开始做系统辨识”的最低条件，不等于完成农艺有效性验证，更不支持节水、增产或肥效结论。

## 最低采集条件

每个采集分区至少需要以下同步记录：

1. 根区浅层和深层各1个体积含水率观测。当前模板使用10 cm和25 cm；若作物实际根层不同，应在采集前修改列名和配置并记录依据，不能采集后按结果移动深度。
2. 控制器灌水命令、每个采样区间的实际灌水深、平均流量和累计水量。分区面积必须已知，便于用`1 mm × 1 m² = 1 L`核对水量账。
3. 棚内空气温度、相对湿度和太阳辐射。若具备净辐射、风速或叶面积指数，可作为扩展列保留。
4. 每个深度每个湿干循环至少2次人工参考含水率。建议在灌水前和湿润后/干燥末期取样；参考方法、环刀体积、湿土质量、干土质量和烘干条件应另存原始记录。
5. 作物生育阶段、根深、传感器状态、场地和分区标识。所有时间使用带时区的ISO 8601格式并统一转为UTC。

建议采样间隔为5至15 min。每行时间戳表示一个采样区间的结束时刻；该行水分是区间末观测，该行流量、实际灌水和气象量对应“上一行时间戳之后至本行时间戳”的区间。每个循环首行只作为初始状态，区间输入填0或空值，不构成转移。模型由第`k−1`行状态预测第`k`行状态时必须使用第`k`行输入。模板把流量定义为该区间的平均流量，把`irrigation_delivered_mm`定义为该区间的水深增量，把`cumulative_water_l`定义为本循环起点归零后的累计水量。原始传感器文件应只读保存到`data/raw/`，清洗和单位转换结果写入`data/interim/`，通过质量闸门且冻结的数据才可进入`data/processed/`。

## 循环与数据划分

一个完整湿干循环必须包含灌水前基线、灌水后水分上升和随后的干燥段。质量闸门要求浅层和深层观测均至少上升0.010 m³/m³，并从峰值回落0.008 m³/m³。这两个数值只用于排除缺乏动态信息的记录，不是作物适宜区间或红壤农艺阈值。

最低门槛为3个完整循环用于辨识，另有2个完整循环只用于验证。`dataset_role`必须在建模前固定为`identification`或`validation`；同一“场地＋分区＋循环”不能跨角色。验证循环不得参与参数选择、结构选择、滤波调参或异常阈值设定。三加二只能支撑可行性研究；若不同生育阶段、土壤层次和灌水强度差异较大，应增加独立循环，而不是把多个采样时刻当作独立重复。

## CSV字段

正式空模板位于`data/templates/field_observation_template.csv`。

| 字段 | 单位/取值 | 含义 |
|---|---|---|
| timestamp_utc | ISO 8601 | 带时区的观测时间 |
| site_id, zone_id, cycle_id | 文本 | 场地、分区和湿干循环标识 |
| dataset_role | identification/validation | 预先冻结的数据用途 |
| sample_interval_minutes | min | 当前行代表的采样区间 |
| zone_area_m2 | m² | 灌水覆盖面积 |
| theta_10cm_m3_m3, theta_25cm_m3_m3 | m³/m³ | 两深度传感器体积含水率 |
| irrigation_command_mm | mm/interval | 控制器请求水深 |
| irrigation_delivered_mm | mm/interval | 流量计或总量计换算的实际水深增量 |
| flow_l_min | L/min | 当前区间平均流量 |
| cumulative_water_l | L | 本循环起点归零后的累计水量 |
| air_temperature_c | °C | 棚内空气温度 |
| relative_humidity_pct | % | 棚内相对湿度 |
| solar_radiation_w_m2 | W/m² | 棚内太阳辐射 |
| reference_theta_10cm_m3_m3, reference_theta_25cm_m3_m3 | m³/m³ | 人工参考体积含水率，无取样时留空 |
| root_depth_m | m | 当期有效根深估计 |
| crop_stage | 文本 | 生育阶段 |
| sensor_status | ok/calibration_check | 传感器质量状态 |
| notes | 文本 | 操作、异常和维护说明 |

## 自动质量闸门

`configs/field_data_quality_v1.yaml`冻结20项检查：字段完整性、时间格式、主键唯一、标识非空、用途合法、循环不跨用途、3个辨识与2个验证循环、核心传感器缺失率、灌水账完整性、采样间隔上限、传感器与参考水分物理范围、环境与灌水范围、采样间断、双深度湿润—干燥响应、参考样本数、流量—水深一致性、累计表单调性和传感器状态。

流量核对使用：

```text
流量积分体积 = Σ(区间平均流量 × 区间分钟数)
水深换算体积 = Σ(区间实际水深 × 分区面积)
累计表增量 = 循环末累计水量 − 循环初累计水量
```

流量积分体积、累计表增量分别与水深换算体积的相对误差当前均不得超过20%。该阈值是首轮工程质量线，取得具体流量计精度、脉冲分辨率和标定数据后必须重新冻结。

运行方式：

```bash
python scripts/validate_field_data.py data/interim/待检查文件.csv \
  --output data/processed/对应质量报告.json
```

程序以退出码0表示全部闸门通过，以退出码2表示失败。通过只说明数据结构和最低动态信息满足后续辨识入口要求，不说明模型已经准确。

## 合成示例的边界

`data/examples/synthetic_field_observations_v1.csv`含240条合成记录，仅用于验证模板和检查程序。它人为满足3个辨识循环、2个验证循环、双深度动态、参考取样和水量账，不代表红壤参数、传感器噪声、真实蒸散或灌溉均匀性。其质量报告不得进入论文的现场结果部分。
