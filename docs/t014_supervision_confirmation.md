# T014 可信监督锁定确认性评价

## 评价范围

评价使用预先冻结的120个锁定异常场景，每类异常10个。基础MPC、固定判据回退和可信监督共享控制器、虚拟对象、扰动、噪声与异常日程，共完成360次闭环运行。异常窗口定义为异常开始至异常结束后48步，主要判据为可信监督相对基础MPC的事件窗口水分亏缺积分配对差。

本次实现审查修正了两项不涉及控制参数的协议问题：根深和排水突变在清单规定的半开时间窗结束后恢复标称参数；场景行显式复制，避免数据视图赋值告警。修正原因来自预设异常时序语义，不依据结果方向选择。

类型层面只有求解失败达到预设改善阈值，中位事件亏缺差为−0.003236。反馈冲突、流量衰减、传感偏置、传感漂移、传感缺测和阀门卡滞共6类出现中位恶化，其中流量衰减为+0.243449、传感缺测为+0.196242、阀门卡滞为+0.104570。

## 机制诊断

连续风险量能够触发模式切换，但当前执行策略不能把检测稳定转化为水分控制收益。流量衰减和阀门卡滞的中位检测延迟分别为2.5步和3步，但可信监督在两类场景的非MPC占比分别达到18.60%和23.66%，事件亏缺仍明显增加。传感缺测、尖峰和偏置发生后，规则回退继续使用最近值或受污染观测；安全暂停又把灌水命令置零，因而在缺水侧异常中可能扩大亏缺。

正常场景仍有4.46%的非MPC占用率和4.5次模式切换中位数，说明开发正常轨迹分位数校准控制了占用时间，但没有消除误触发和模式抖动。当前证据支持保留风险监测器与状态机框架，不支持将现有回退控制律作为毕业论文的最终算法贡献。

## 后续边界

下一版只能在新的开发异常集上设计，锁定T014结果不得用于修改后重新宣称同一次确认性成功。优先修正方向为：在观测不可信时使用独立状态估计或保守水量包络；将执行异常下的命令、反馈和实际可达灌水量分开；为安全暂停设置根区含水量下限触发的有限应急灌水；降低恢复阶段的反复切换。完成开发后必须生成新的监督版本和独立锁定场景，作为第二次确认性试验。
