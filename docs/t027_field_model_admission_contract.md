# T027 现场数据模型准入两级闸门协议

## 目的

T023只能判断文件结构、循环数量、动态、水分参考和灌水账是否合格。T026说明即使循环数量相同，重复的初始状态、灌水和天气输入仍可能缺乏参数信息。T027将两者串联，输出以下三种明确决策：

- `blocked_data_quality`：基础质量检查失败，不计算信息量；
- `collect_more_excitation`：基础质量通过，但用于辨识的数据量、矩阵秩或信息强度不足；
- `provisional_ready_for_identification`：两级检查均通过，可进入参数拟合和独立验证。

准入只使用预先标为`identification`的循环，`validation`循环不进入信息矩阵。

## 冻结计算

每个辨识循环只构造循环内部相邻时刻的转移，不跨循环连接。按现场模板的区间结束时间语义，由第`k−1`行状态预测第`k`行状态时，实际灌水、太阳辐射及由温湿度计算的VPD均取第`k`行。设计矩阵包含浅深层水分差、实际灌水深、太阳辐射、VPD以及截距。至少需要120个可用转移、可用比例不低于95%，矩阵秩必须达到5。

参数尺度沿用T026的双层灰箱边界。差分噪声暂按测量标准差0.0005 m³/m³和过程标准差0.0001 m³/m³计算。参考T026中等激励水平，最弱层的最小奇异值不得低于28，合并预测归一化标准误RMS不得高于0.018。

上述噪声和阈值来自合成试验，只能形成`provisional_ready_for_identification`。取得传感器重复标定和实测模型残差后，必须另行冻结现场版本，不能把当前绝对阈值直接称为红壤有效标准。

## 软件验收

冻结的240行合成接入样例应继续通过T023质量检查，但因三个辨识循环的激励基本重复，应输出`collect_more_excitation`。验收同时要求：

- 只使用3个辨识循环的141个循环内转移；
- 设计矩阵满秩；
- 修改验证循环不得改变信息矩阵；
- 基础质量失败时不得继续给出信息量结果；
- 相同输入连续运行的JSON结果完全一致。

该预期失败决策表示闸门正确阻止信息不足的数据进入模型冻结，不表示软件任务失败。
