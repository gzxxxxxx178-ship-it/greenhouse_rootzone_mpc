# T029 毕业设计证据审计协议

## 目标

本任务把任务台账、毕业设计证据矩阵、冻结JSON结果和论文主张边界连接为一次可重复检查。审计通过只表示仓库内部证据一致、关键数字可回溯，不代表缺失的红壤或实体证据已经取得。

## 审计对象

审计固定检查：

1. `task_list.csv`中的任务编号、状态、完成日期和证据路径；
2. `thesis_evidence_matrix.csv`中的状态、证据路径，以及预期保留的缺失、失败和停止项；
3. 审计配置列出的核心结果文件正式状态或分类；
4. 配置列出的结果文件与冻结配置哈希绑定；
5. 结果中记录的Git提交是否仍存在；
6. 配置列出的论文关键数字是否与JSON来源一致；
7. 支持、条件支持和禁止使用三类主张是否与需求状态一致；
8. 仿真软件版、红壤模型版和实体效果版三种毕业设计成熟度。

失败和停止结果属于有效学术证据，不会因为状态不是`completed`而被删除。R005、R006、R007和R015必须保持失败或停止，除非另有新任务和独立证据；R003、R009和R010在真实数据到位前必须保持缺失。

## 主张规则

“支持”主张要求绑定需求全部处于`completed`或`ready`。条件主张只要仍有需求缺失、失败或停止，就必须保持`conditional`。禁止主张不会因其他状态变化被自动升级，必须通过修改审计协议并提供新的冻结证据才能解除。

## 运行与判定

```bash
python scripts/audit_thesis_evidence.py
```

结果写入`data/processed/thesis_evidence_audit_v1.json`。全部仓库一致性检查通过时脚本退出码为0；任一证据路径、结果状态、配置哈希、Git提交或关键数字不匹配时退出码为2。本任务不生成图形。
